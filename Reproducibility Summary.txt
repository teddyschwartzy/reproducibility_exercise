Reproducibility SummaryThe biggest reproducibility challenges in this analysis were handling missing clinical data and controlling for randomness within the machine learning and bootstrapping procedures. Several clinical variables, including glucose and BMI, contained values of zero that are not biologically realistic and likely represent missing observations. If these values are treated differently across environments or runs, summary statistics and hypothesis test results can change.To address this issue, I created a reusable clean_clinical_data() function that identifies biological zeros and replaces them with median-imputed values. I also defined a global RANDOM_STATE = 42 to ensure that train-test splits, model training, and bootstrap sampling produce the same results each time the analysis is executed. In addition, I used a centralized CONFIG dictionary to store key settings and variables, which reduces hard-coded values and makes the workflow easier to reproduce across different systems and datasets.To verify reproducibility, I restarted the Jupyter kernel and ran the entire notebook from beginning to end. After the rerun, I compared the machine learning performance metrics, p-values, and bootstrap estimates to the original results. The outputs remained unchanged, indicating that the workflow is fully reproducible and can be executed consistently by other users.
